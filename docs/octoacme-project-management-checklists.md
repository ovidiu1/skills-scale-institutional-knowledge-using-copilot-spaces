# OctoAcme Project Management Checklists

This document provides checklists to support consistent planning, execution, release, and review processes.

## Planning Checklist
- [ ] Kickoff meeting scheduled with stakeholders and delivery team
- [ ] Project scope and objectives documented
- [ ] Backlog items prioritized and estimated
- [ ] Acceptance criteria defined for key features
- [ ] Definition of Done documented
- [ ] Release timeline and milestones agreed
- [ ] Decision Log / Change Register created
- [ ] Roles, approvals, and handoffs clarified
- [ ] Initial test and QA approach drafted

## Execution Checklist
- [ ] Project board columns and workflow agreed
- [ ] PR conventions and review expectations documented
- [ ] CI/linting pipelines configured
- [ ] Daily standups and weekly syncs scheduled
- [ ] Risk register reviewed and updated regularly
- [ ] Decision Log updated for key trade-offs and escalations
- [ ] Action items tracked after demos and planning sessions
- [ ] Stakeholder updates prepared for major milestones

## Release Checklist
- [ ] All acceptance criteria met and merged
- [ ] Passing CI and security scans
- [ ] Release notes drafted and reviewed
- [ ] Rollback / mitigation plan documented
- [ ] Staging smoke tests completed
- [ ] Production deployment plan confirmed
- [ ] Post-deploy verifications defined
- [ ] Release announcement shared with stakeholders and support
- [ ] Post-release review scheduled

## Retrospective Checklist
- [ ] Retrospective session scheduled soon after release
- [ ] Successes and challenges captured
- [ ] Root causes identified without blame
- [ ] Action items assigned with owners and due dates
- [ ] Follow-up on prior retrospective actions
- [ ] Share outcomes and improvements with the team

## Decision & Change Control Checklist
- [ ] Key decisions documented in a Decision Log
- [ ] Change requests assessed for impact and approval needs
- [ ] Approval owners identified for scope, timeline, and quality changes
- [ ] Communication plan updated for affected stakeholders
- [ ] Decision Log and issue history referenced in reviews
- [ ] Lessons learned added to project documentation
